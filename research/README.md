# Research

This folder is the evidence base for Gitty. It is deliberately separate from:

- `captured-ideas-<username>.md`: raw, personal mobile captures.
- `_bmad-output/`: planning and implementation records.
- GitHub Issues: public discussion or work that needs external coordination.

## Start here

1. [Workflow and product direction](./workflow-and-product-direction.md) — what we know, what is still an assumption, and the recommended product boundary.
2. [Outreach playbook](./outreach.md) — who to contact, where to find them, what to ask, and how to log evidence.

## Research rule

We are validating a concrete behaviour, not collecting feature votes:

> A developer captures an idea away from the laptop, sees it once when they return, deliberately routes it into real work, and can later prove what happened to it.

Do not build a broader agent orchestration layer until five conversations either validate or kill that behaviour.

## Evidence standard

- Ask about a specific moment in the last seven days.
- Ask to see the terminal, IDE, GitHub issue, task file, or commit.
- Record the exact workaround and cost in time, money, or lost work.
- Treat "that sounds useful" as no evidence.
- After five interviews, write `ai-native-devs-findings-v1.md` against the three hypotheses in the workflow document.
