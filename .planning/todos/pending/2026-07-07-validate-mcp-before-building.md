## Problem

MCP is strategically attractive, but building it now would be premature. The existing repo notes already defer MCP, CLI, and extensions until real user conversations happen. Fable's suggestion is directionally good, but it should not become another internal build project before the core trust issues and positioning are validated.

The shipping risk is productive procrastination: building a polished integration before proving that AI-first developers actually want Gitty's mobile capture to agent handoff loop.

## Solution

Validate first. Prepare one demo loop and run 5 direct conversations with AI-first developers: "Where do your agent tasks currently get lost?" and "Would a mobile inbox that your agent reads every session replace your current capture flow?" Also post one short demo in a relevant AI-dev community. Only build MCP if the response clearly shows that AGENTS.md plus markdown is not enough.
